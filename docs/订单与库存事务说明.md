# 订单与库存事务说明

## 1. 模块位置

订单功能按 Maven 模块拆分，没有把 Controller、SQL 和业务判断写在一起：

```text
smartmall-web             HTTP 接口、请求校验、响应 DTO
        ↓
smartmall-business        订单规则、状态流转、事务边界、仓储接口
        ↓
smartmall-infrastructure  MyBatis 实体、Mapper、仓储实现和 SQL
        ↓
PostgreSQL                orders、order_item、product、customer
```

数据库建表脚本位于：

```text
backend/smartmall-application/src/main/resources/db/migration/V3__create_order_tables.sql
```

Flyway 执行过 `V3` 后不要直接修改该文件。后续表结构变化应新增 `V4`，否则 Flyway 校验会失败。

## 2. 接口

| 方法 | 地址 | 作用 |
| --- | --- | --- |
| `GET` | `/api/orders` | 分页查询，可按订单号、客户名称和状态筛选 |
| `GET` | `/api/orders/{id}` | 查询订单及商品明细 |
| `POST` | `/api/orders` | 创建订单并扣减库存 |
| `POST` | `/api/orders/{id}/pay` | 模拟支付 |
| `POST` | `/api/orders/{id}/cancel` | 取消未支付订单并恢复库存 |

创建订单只接收客户 ID、商品 ID 和数量：

```json
{
  "customerId": 1,
  "items": [
    { "productId": 2, "quantity": 3 }
  ]
}
```

前端不提交商品名称、SKU、单价、总金额和订单状态。这些数据由后端读取或计算，避免浏览器伪造价格。

## 3. 创建订单调用链

```text
OrdersView.vue
  → orderApi.create
  → POST /api/orders
  → OrderController.create
  → OrderService.create（事务开始）
      → CustomerRepository.findById
      → ProductRepository.findById
      → ProductRepository.reserveStock
      → OrderRepository.insert
  → OrderService.create（事务提交）
  → 返回完整订单
```

`OrderService` 会先合并重复商品项，再使用数据库中的真实价格计算小计和总额。订单明细保存的是下单时的 SKU、名称和单价快照，之后修改商品不会影响历史订单。

## 4. 为什么并发下不会超卖

库存不是先在 Java 中判断再普通更新，而是由一条带条件的 SQL 完成：

```sql
UPDATE product
SET stock = stock - :quantity
WHERE id = :productId
  AND active = TRUE
  AND stock >= :quantity;
```

数据库返回受影响行数：

- `1`：扣减成功。
- `0`：商品停用、商品不存在，或者库存已被其他请求抢先占用。

例如库存只有 1，两笔请求同时购买 1 件，第一笔更新后库存变成 0，第二笔的 `stock >= 1` 不再成立，因此第二笔不会继续创建订单。

订单创建在同一个 Spring 事务中执行。任一商品扣减失败、金额超限或订单保存失败，之前执行的库存扣减都会随事务一起回滚。

## 5. 支付与取消

当前状态流转为：

```text
PENDING_PAYMENT → PAID
PENDING_PAYMENT → CANCELLED
```

支付和取消 SQL 都包含：

```sql
WHERE id = :id AND status = 'PENDING_PAYMENT'
```

因此两个请求同时操作同一订单时，只会有一个状态更新成功。取消成功后，业务服务根据订单明细恢复库存；恢复库存与取消状态也处于同一事务中。

本阶段的“支付”只修改项目内部状态，不连接微信、支付宝或真实资金渠道。

## 6. 前端页面

`frontend/src/views/OrdersView.vue` 负责页面状态和交互，`frontend/src/api/orders.ts` 只负责 HTTP 请求。页面支持：

- 订单分页、关键字搜索和状态筛选
- 从现有客户和上架商品中创建订单
- 按数据库商品价格预览金额
- 查看订单明细和价格快照
- 对待支付订单执行模拟支付或取消

前端金额预览只用于交互提示，最终金额仍以后端返回结果为准。
