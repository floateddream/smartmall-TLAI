# SmartMall TLAI 后台功能验收指南

本文用于验收后台页面、AI 调用日志、工具卡联动、审计关联和 RBAC。文档不包含账号密码、模型 API Key、数据库口令或服务密钥；验收人员应使用自己的本地安全配置。

## 1. 功能范围

### AI 调用日志

- 对 CHAT、EMBEDDING 和模型连通性测试记录统一的安全运行元数据。
- 支持模型类型、供应商、调用场景、成功/失败状态筛选及分页。
- 列表和详情只展示模型、场景、状态、耗时、输入输出规模、错误码等元数据。
- 不保存或返回 API Key、鉴权头、完整 Prompt、用户输入、模型回答、向量内容和供应商响应正文。

### AI 工具卡业务联动

- 订单、退款、工单、知识库和数据分析工具结果可跳转到对应后台页面。
- 目标路径由 Java 后端固定映射，模型不能指定任意路径。
- 后端和前端分别执行参数白名单校验；未知路径、非法枚举、非法 ID、超长关键字、控制字符和无效日期范围不会被应用。
- 历史消息没有 `navigation` 字段时仍可正常读取，只是不显示跳转按钮。
- 当前账号缺少目标页面权限时，历史工具卡不显示跳转入口；目标接口仍由后端 RBAC 独立保护。

### 审计体验整合

- Agent 审计和 AI 调用日志提供统一的筛选、分页、加载、空状态、失败重试和安全详情抽屉。
- 每次持久化会话回复生成 UUID `traceId`，同时携带明确的 `conversationId`；同次 Agent 工具审计和模型调用使用相同 `traceId`。
- 两类审计可按 `traceId` 精确联动，不按时间、用户名或相似内容猜测。
- Agent 审计只向浏览器返回参数字段名，不返回参数值或工具业务结果。
- 会话入口只对会话所有者本人且拥有 `ai:chat` 权限时显示，后端始终再次校验所有权。
- 历史记录的关联字段为空时显示“历史记录未关联”，不影响列表和详情查看。

### 后台完整性与交互状态

- 为审计页、AI 助手会话、数据分析审计、用户与权限、模型配置补齐持久失败状态和重试入口。
- 列表、详情和会话切换使用请求序号隔离；快速切换筛选、分页或历史会话时，旧响应不会覆盖新状态。
- 所有分页列表在数据变化导致当前页越界时自动回到最后一个有效页。
- 多条件页面提供筛选重置；加载和写操作期间禁用重复操作入口。
- 工具卡跳转同时校验参数白名单和目标页面权限。
- 表格、详情、审计字段和聊天内容处理长文本溢出；窄屏时保留横向滚动或切换为单列布局。
- 按钮使用原生 `button`、可见焦点、`aria-label`、`role="status"` 或 `role="alert"` 等基本键盘和辅助技术语义。

## 2. 实际后台页面和页面权限

以下清单以 `frontend/src/router/index.ts` 和 `ConsoleLayout.vue` 为准，共 13 个后台页面：

| 菜单分组 | 页面 | 路由 | 页面权限 |
| --- | --- | --- | --- |
| 总览 | 仪表盘 | `/dashboard` | `dashboard:view` |
| 业务运营 | 商品管理 | `/products` | `product:view` |
| 业务运营 | 客户管理 | `/customers` | `customer:view` |
| 业务运营 | 订单管理 | `/orders` | `order:view` |
| 业务运营 | 退款管理 | `/refunds` | `refund:view` |
| 业务运营 | 售后工单 | `/tickets` | `ticket:view` |
| 智能工作台 | AI 助手 | `/assistant` | `ai:chat` |
| 智能工作台 | 知识库 | `/knowledge` | `knowledge:view` |
| 智能工作台 | 数据分析 | `/data-analysis` | `analytics:view` |
| 智能工作台 | Agent 审计 | `/agent-audits` | `agent:audit_view` |
| 系统设置 | 用户与权限 | `/access-control` | `system:user_view` |
| 系统设置 | 模型配置 | `/models` | `system:model_manage` |
| 系统设置 | 调用日志 | `/ai-call-logs` | `ai:call_log_view` |

菜单和路由守卫只改善导航体验。所有读取、创建、审核、状态推进和系统管理接口继续使用 `@PreAuthorize` 校验对应权限；隐藏菜单不构成接口保护。

页面内写操作继续使用更细权限，例如 `product:manage`、`order:create`、`order:pay`、`refund:review`、`ticket:reply`、`system:user_manage` 和 `system:rbac_manage`。内置管理员通过迁移获得新增权限，已有自定义角色可由管理员在权限矩阵中按需授予。

## 3. 数据库迁移

### V15

`V15__create_ai_call_log.sql`：

- 创建 `ai_call_log`、时间和筛选索引；
- 创建 `ai:call_log_view` 权限；
- 将新权限授予内置 `ADMIN` 角色，兼容已有管理员数据。

### V16

`V16__link_ai_audit_records.sql`：

- 为 `agent_tool_audit` 和 `ai_call_log` 增加可空 `trace_id`、`conversation_id`；
- `conversation_id` 使用外键并在会话删除时置空；
- 为非空追踪标识和会话标识建立索引；
- 不回填或猜测历史关联，历史数据保持 `NULL`。

后端使用包含数据库连接配置的本地 profile 启动时，Flyway 会自动顺序执行未应用迁移。不要修改已经执行过的 V15/V16，也不要在未确认数据库状态时执行 `repair`。本验收不要求手工执行 SQL。

## 4. 验收前置条件

- JDK 21、Maven 3.9+、Node.js 22.12+、pnpm 10 和项目锁定的前端依赖可用。
- PostgreSQL、Redis 和对象存储等项目依赖服务可连接。
- 本地后端配置文件已准备好，但不得将其密钥或口令提交到 Git。
- 至少准备：
  - 一个拥有后台页面及审计权限的管理员账号；
  - 一个只拥有部分业务查看权限的受限账号；
  - 可选的第二个拥有 `ai:chat` 的账号，用于验证会话所有权隔离。
- 至少存在一个可用 CHAT 模型。若要验收知识库向量化，还需可用 EMBEDDING 模型和测试文档。
- 业务库中准备少量真实测试商品、客户、订单、退款和工单；不要在源码中添加写死的演示数据。

## 5. 启动方式

1. 在项目已有的安全本地配置下启动后端，确认日志显示 Flyway 已成功迁移且应用启动完成。
2. 在安装了 Node.js 22.12+ 和 pnpm 10 的终端中，从仓库根目录启动前端：

```bash
cd frontend
node -v
pnpm install --frozen-lockfile
pnpm dev
```

3. 打开 `http://127.0.0.1:5173`。详细启动和停止方式见《本地启动指南.md》。

## 6. 逐项验收

### A. 后台页面完整性

1. 使用管理员依次打开第 2 节的 13 个页面。
2. 对每个列表检查首次加载、空筛选结果、接口失败后的可见提示和重试。
3. 快速切换筛选和分页，确认最终显示最后一次操作对应的数据。
4. 在最后一页删除或改变数据后刷新，确认自动回到有效页。
5. 检查多条件筛选重置、窄屏横向滚动、长标题/错误码/地址，以及键盘 Tab 焦点。
6. 连续点击保存、审核、推进、启停、测试等按钮，确认处理中不会重复提交。

### B. AI 调用日志

1. 在“模型配置”执行一次成功的连通性测试；再用不可用测试配置触发一次可控失败。
2. 打开“调用日志”，分别筛选成功、失败、模型类型、供应商和场景。
3. 打开详情，确认只包含安全元数据，不含 Prompt、回答、API Key、鉴权头或供应商正文。
4. 输入非法筛选值直接请求后端，确认返回统一错误且不能绕过 `ai:call_log_view`。

### C. 工具卡和刷新兼容

1. 在 AI 助手查询具体订单、退款或工单，点击工具卡“查看”。
2. 确认目标页应用合法 ID、关键字或状态，并能在刷新后保持正常。
3. 手工构造未知路径、非法 ID、非法状态、超长关键字和额外 `redirect` 参数，确认无任意跳转且非法条件不生效。
4. 打开数据库迁移 V16 以前的历史会话，确认无导航字段的旧工具卡仍可展示。
5. 撤销账号的目标页面权限并重新登录，确认工具卡不再显示入口，直接访问页面和接口也被拒绝。

### D. 审计关联和会话隔离

1. 在助手完成一次会调用业务工具的查询。
2. 打开 Agent 审计详情，确认只显示参数字段名，不显示参数值、工具结果、Prompt 或回答。
3. 从 Agent 审计跳转到相同 `traceId` 的 AI 调用日志，确认是同一次请求的精确记录。
4. 使用会话所有者点击会话入口，确认能打开关联历史；换用另一个账号直接请求同一会话 ID，确认无法读取。
5. 查看 V16 以前的记录，确认显示“历史记录未关联”且详情、筛选和分页正常。
6. 测试不存在的记录、无权访问的目标页和不可访问会话，确认页面显示明确失败提示或不展示入口。

### E. RBAC

1. 使用管理员确认菜单、路由和按钮与权限矩阵一致。
2. 使用受限账号确认无权限菜单不显示。
3. 直接请求受限接口，确认后端返回 403，而不是只依赖前端隐藏。
4. 给自定义角色授予或撤销 `agent:audit_view`、`ai:call_log_view`，重新登录后确认入口和接口同步变化。

## 8. 已知非阻塞提示

- Maven 测试可能显示 Mockito 动态 Java Agent 的未来兼容提示，不影响当前测试结果。
- Vite 生产构建可能提示部分 chunk 超过 500 kB；这是优化建议，不影响构建产物正确性。
- SSE 当前是在完整模型结果生成后分片发送，不是供应商原生 token 流；浏览器中止接收不能保证供应商请求立即取消，重新打开会话可查看服务端最终保存的结果。
- 历史审计数据不会自动生成 `traceId` 或 `conversationId`，这是有意的安全兼容策略。
