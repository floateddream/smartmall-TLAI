# 前后端交互与菜单路由

这份文档按当前代码说明浏览器如何调用 Spring Boot，以及点击左侧菜单后页面如何切换。先记住两个不同的动作：**请求接口**是向后端获取或提交数据；**切换路由**是在前端决定显示哪个页面。点击菜单不一定会请求接口。

## 1. 从浏览器到后端

本地开发时，浏览器打开 `http://127.0.0.1:5173`，这是 Vite 前端服务；Spring Boot 运行在本机 `127.0.0.1:8080`。PostgreSQL 位于服务器，由 Spring Boot 连接，浏览器不直接连接数据库。

```text
浏览器页面 (127.0.0.1:5173)
  -> Vue 页面组件
  -> Pinia auth store
  -> Axios: /api/auth/login
  -> Vite 代理 (127.0.0.1:5173 -> 127.0.0.1:8080)
  -> Spring Security 过滤器链
  -> AuthController -> AuthService -> 用户服务/数据库
  <- ApiResponse JSON <- Axios <- 页面更新
```

- [frontend/vite.config.ts](../frontend/vite.config.ts)：开发服务器把 `/api`、`/actuator` 转发到后端。浏览器网络面板仍会看到 `127.0.0.1:5173/api/...`。
- [frontend/src/api/client.ts](../frontend/src/api/client.ts)：业务接口统一使用 `baseURL: '/api'` 的 Axios 实例，超时为 15 秒。
- [SecurityConfig.java](../backend/smartmall-security/src/main/java/com/smartmall/tlai/security/SecurityConfig.java)：先决定哪些请求公开、哪些必须登录；后端不使用 HTTP Session。
- [ApiResponse.java](../backend/smartmall-common/src/main/java/com/smartmall/tlai/common/api/ApiResponse.java)：业务接口统一返回 `code`、`message`、`data`。

例如前端调用 `api.post('/auth/login', ...)`，实际请求路径是 `/api/auth/login`。Vite 代理只服务于**本地开发**；将来部署时要另行配置前端服务器或 Nginx 的 `/api` 转发。代理和后端的 CORS 白名单是两个概念：代理解决本地开发的转发，CORS 约束浏览器跨源直连后端时允许的 Origin。

仪表盘的健康检查是一个例外：它直接用 Axios 请求 `/actuator/health`，走 Vite 的另一条代理规则，不经过业务 Axios 实例的 Token 和错误拦截器。

## 2. 注册：表单数据怎样入库

```text
/register 表单
  -> RegisterView.submit() 前端校验
  -> auth.register() (Pinia)
  -> POST /api/auth/register
  -> AuthController.register() 的 @Valid 校验
  -> AuthService.register() 固定角色 OPERATOR
  -> UserAccountService.createUser()
  -> BCrypt 加密密码 -> UserMapper 写入 PostgreSQL app_user
  <- HTTP 201 + 用户信息（不含密码哈希）
  -> 前端跳转 /login
```

对应代码：[RegisterView.vue](../frontend/src/views/RegisterView.vue)、[auth.ts](../frontend/src/stores/auth.ts)、[AuthController.java](../backend/smartmall-web/src/main/java/com/smartmall/tlai/web/auth/AuthController.java)、[AuthService.java](../backend/smartmall-security/src/main/java/com/smartmall/tlai/security/auth/AuthService.java)、[UserAccountService.java](../backend/smartmall-business/src/main/java/com/smartmall/tlai/business/user/application/UserAccountService.java)。

请求体示意（不要使用真实密码做文档示例）：

```json
{"username":"demo_user","email":"demo@example.com","password":"Example123"}
```

成功响应的形状如下；`id` 由数据库生成：

```json
{"code":"SUCCESS","message":"操作成功","data":{"id":1,"username":"demo_user","email":"demo@example.com","roles":["OPERATOR"],"permissions":["dashboard:view","product:view"],"enabled":true}}
```

前端的校验改善输入体验，后端的 `@Valid`、唯一约束和业务校验才是最终判断。普通注册接口不接收角色字段，因此不能通过表单把自己注册为 `ADMIN`。用户名区分大小写，邮箱保存前转小写。

## 3. 登录：密码验证和 Token

```text
/login 输入用户名或邮箱 + 密码
  -> LoginView.submit() 校验并去掉 account 两端空格
  -> auth.login() -> POST /api/auth/login
  -> AuthService.login()
  -> AuthenticationManager -> DatabaseUserDetailsService
  -> 查询 app_user，BCrypt 比对输入密码与保存的哈希
  -> JwtService 签发 JWT Access Token
  <- HTTP 200 + data.accessToken、data.user、data.expiresIn
  -> Pinia 保存 user，localStorage 保存 Token
  -> Vue Router 跳转 /dashboard（或原本想访问的受保护页面）
```

相关文件：[LoginView.vue](../frontend/src/views/LoginView.vue)、[DatabaseUserDetailsService.java](../backend/smartmall-security/src/main/java/com/smartmall/tlai/security/DatabaseUserDetailsService.java)、[AuthService.java](../backend/smartmall-security/src/main/java/com/smartmall/tlai/security/auth/AuthService.java)。`expiresIn` 单位为秒。本阶段没有 Refresh Token，过期后需要重新登录。

登录请求使用 `account` 字段，既可以填用户名，也可以填邮箱：

```json
{"account":"demo_user","password":"Example123"}
```

成功响应只展示结构，不展示真实 Token：

```json
{"code":"SUCCESS","message":"操作成功","data":{"tokenType":"Bearer","accessToken":"<JWT>","expiresIn":3600,"user":{"id":1,"username":"demo_user","email":"demo@example.com","roles":["OPERATOR"],"permissions":["dashboard:view","product:view"],"enabled":true}}}
```

上面的 `expiresIn` 数值只是格式示意，实际有效期以运行配置返回值为准。登录失败时后端返回 HTTP 401 / `INVALID_CREDENTIALS`，登录表单展示错误；业务请求的全局“401 退出”不会把这次登录失败当作已有会话过期。

## 4. 刷新页面、带 Token 请求和退出

Token 和用户信息不是存放在同一个地方：[auth.ts](../frontend/src/stores/auth.ts) 初始化时从 `localStorage` 读取 Token；用户信息只在当前 Pinia 内存状态中。浏览器刷新后，内存清空，但 Token 还在，路由守卫调用 `auth.restore()` 请求 `GET /api/auth/me`，取回当前用户信息，再进入目标页面。

```text

刷新 /dashboard
  -> Vue Router 导航守卫
  -> auth.restore() 读取已有 Token
  -> Axios 请求拦截器加 Authorization: Bearer <JWT>
  -> GET /api/auth/me
  -> JwtAuthenticationFilter 校验 JWT，并从数据库重新加载用户
  -> SecurityContext 放入当前认证用户
  -> AuthController.me() 返回用户信息
  -> Pinia 恢复 user -> 显示仪表盘
```

过滤器会重新查用户，以检查账号是否仍然存在、可用；不能仅凭前端保存的用户名判断已经登录。见 [JwtAuthenticationFilter.java](../backend/smartmall-security/src/main/java/com/smartmall/tlai/security/JwtAuthenticationFilter.java)。后续使用同一个 `api` 实例发起的业务请求，也会由请求拦截器自动附带 Token。

当 Token 无效或过期，后端返回 401；Axios 响应拦截器触发全局处理，清除 Token 和用户信息，并返回登录页。若刷新时 `/me` 恢复失败，路由守卫也会转到登录页。点击“退出登录”则直接清理浏览器中的 Token 和 Pinia 用户状态并跳转 `/login`，当前没有服务端 Token 撤销接口。

**401 与 403 不同**：401 是未认证或 Token 无效；403 是已登录但角色不足。`/api/admin/**` 由后端要求 `ADMIN`，不是依赖前端菜单是否显示。前端的管理员菜单只负责体验，不能当作权限保护。

## 5. 菜单与路由：点一下究竟发生什么

这里有三份职责，不要把它们混成一份：

| 位置 | 职责 |
| --- | --- |
| [ConsoleLayout.vue](../frontend/src/layouts/ConsoleLayout.vue) 的 `groups` | 定义左侧可见菜单的分组、文字、图标和目标 `path`；`ADMIN` 才显示“模型配置”。 |
| [router/index.ts](../frontend/src/router/index.ts) 的 `routes` | 将 URL 路径映射到页面组件，配置标题及是否是访客页或管理员页。 |
| `<router-view>` | [App.vue](../frontend/src/App.vue) 显示顶层页面；后台布局里的第二个 `<router-view>` 显示当前子页面。 |

以点击“商品管理”为例：

```text
点击 <router-link to="/products">
  -> Vue Router 将地址变成 /products（通常不整页刷新）
  -> beforeEach 守卫调用 auth.restore() 判断登录态
  -> 查到 routes 中 / 的子路由 products
  -> App.vue 渲染 ConsoleLayout.vue
  -> ConsoleLayout.vue 的 <router-view> 渲染 ProductsView.vue
  -> route.meta.title 显示在顶部面包屑；活跃菜单自动高亮
```

`/dashboard` 对应 `DashboardView.vue`；`/products`、`/customers`、`/orders`、`/refunds`、`/tickets` 分别对应各自真实业务页面，进入页面后会调用后端分页接口。`/assistant` 和 `/models` 已接入真实 AI 接口，`/knowledge` 仍对应 `ModuleView.vue` 占位页。仪表盘的经营指标、趋势、近期订单仍是演示数据；用户名和 `/actuator/health` 状态来自真实接口。

菜单数组和路由表目前是分别维护的：新增菜单时，还要在路由表中有对应路径；新增路由不意味着它自动出现在菜单。移动端打开菜单、桌面端收起侧栏只是 `ConsoleLayout.vue` 的本地显示状态；切换路由时会关闭移动端菜单。

## 6. 路由守卫具体判断什么

[router/index.ts](../frontend/src/router/index.ts) 的 `beforeEach` 在页面导航前执行：

1. 调用 `auth.restore()`：没有 Token 返回未登录；有 Token 但内存没有用户时请求 `/api/auth/me`；已有用户时直接复用。
2. 访问 `/login` 或 `/register`：已登录则转到 `/dashboard`，否则允许进入。
3. 访问后台页面：未登录则转到 `/login?redirect=原路径`。
4. 访问标记 `admin: true` 的页面：若用户不是 `ADMIN`，转到 `/dashboard`。
5. 其余路由允许进入；找不到的路径重定向 `/dashboard`。

登录成功时 `LoginView.vue` 会读取 `redirect`，避免登录后忘记原本想去的页面；不可信的外部跳转地址不会直接使用。前端守卫只控制页面导航，后端 `SecurityConfig` 才控制接口的真实授权。

## 7. 自己调试一条请求

在 Chrome 按 F12 打开开发者工具的 **Network（网络）**，勾选保留日志后按流程观察：

1. 登录：找 `POST /api/auth/login`，看请求体的字段名 `account`、`password`，以及响应的 HTTP 状态和 `data` 结构。不要截图分享密码或完整 Token。
2. 刷新仪表盘：找 `GET /api/auth/me`，看请求头是否有 `Authorization: Bearer ...`，响应 `data.username` 是否是当前账号。
3. 点击“商品管理”：URL 变成 `/products`，随后可看到 `GET /api/products` 分页请求；订单、退款和工单页面同理。
4. 看服务监测：`GET /actuator/health` 是另一条请求；后端正常时返回 `status: UP`。
5. 请求失败先看 HTTP 状态：400 是参数校验、401 是认证、403 是授权、409 常见于用户名或邮箱重复；若没有 HTTP 响应，再检查前后端是否运行及 Vite 代理目标。

注意：Network 中的 Token 可以访问你的账号，调试完不要把完整请求头、真实密码或本地配置发给别人。
