# SmartMall TLAI 本地启动指南

本文用于记录本地开发时的启动、访问和关闭步骤。项目采用前后端分离结构，因此后端和前端需要分别启动。

## 1. 启动前检查

本地需要具备：

```text
JDK 21
Maven 3.9+
Node.js 22.12+
pnpm 10
IntelliJ IDEA（可选）
```

启动前还需要可访问的 PostgreSQL 16（含 pgvector）、Redis 7 和 MinIO。它们既可以运行在本机 Docker 中，也可以由独立开发服务器提供；不要在代码和公开文档中写入真实连接密码。

## 2. 第一次导入或 POM 修改后

使用 IDEA 时，在右侧 Maven 面板点击“重新加载所有 Maven 项目”。使用命令行时，从仓库根目录执行：

```bash
cd backend
mvn test
```

后端父工程是：

```text
backend/pom.xml
```

所有后端模块都由这个父 POM 聚合管理。

## 3. 配置后端启动项

启动类位置：

```text
backend/smartmall-application/src/main/java/com/smartmall/tlai/SmartMallTlaiApplication.java
```

IDEA 运行配置应为：

```text
JRE：Java 21
模块：smartmall-application
主类：com.smartmall.tlai.SmartMallTlaiApplication
有效配置文件：local
```

“有效配置文件”只填写：

```text
local
```

不要在这里填写 `--spring.profiles.active=local`。如果没有“有效配置文件”输入框，也可以改在“程序实参”中填写：

```text
--spring.profiles.active=local
```

两种方式选择一种，不需要同时配置。

本地配置文件位于：

```text
backend/smartmall-application/src/main/resources/application-local.yml
```

该文件包含本地数据库连接和密钥，不应提交到 Git，也不要把内容贴到公开位置。

## 4. 启动后端

可以在 IDEA 中运行 `SmartMallTlaiApplication`，也可以使用 Maven 构建后从命令行启动：

```bash
cd backend
mvn -pl smartmall-application -am package -DskipTests
java -jar smartmall-application/target/smartmall-application-0.0.1-SNAPSHOT.jar --spring.profiles.active=local
```

使用命令行前同样需要准备 `application-local.yml`，或者在当前进程中设置 `application.yml` 所列的 `SMARTMALL_*` 环境变量。

启动过程中会自动执行 Flyway 数据库迁移。如果依赖服务位于远程服务器，首次建立连接可能需要等待数秒。

看到以下日志表示后端启动成功：

```text
Tomcat started on port 8080
Started SmartMallTlaiApplication
```

后端地址：

```text
http://127.0.0.1:8080
```

健康检查地址：

```text
http://127.0.0.1:8080/actuator/health
```

正常响应中应包含：

```json
{"status":"UP"}
```

## 5. 启动前端

确认当前终端使用 Node.js 22.12+ 和 pnpm 10。推荐通过 fnm、nvm、nvm-windows 或 Volta 管理 Node.js 版本，然后从仓库根目录执行：

```bash
cd frontend
node -v
pnpm -v
pnpm install --frozen-lockfile
pnpm dev
```

`node -v` 应显示：

```text
v22.x.x
```

如果尚未安装 pnpm，可以通过 Corepack 启用：

```bash
corepack enable
corepack prepare pnpm@10 --activate
```

看到 Vite 输出本地地址后，在浏览器打开：

```text
http://127.0.0.1:5173
```

前端会把 `/api` 和 `/actuator` 请求代理到本地后端的 `8080` 端口。

## 6. 推荐启动顺序

```text
1. 确认 PostgreSQL、Redis、MinIO 可访问
2. 在 IDEA 或命令行中启动后端
3. 等待后端出现 Started SmartMallTlaiApplication
4. 在 PowerShell 中启动前端
5. 浏览器访问 http://127.0.0.1:5173
```

如果只是修改前端页面，Vite 通常会自动热更新，不需要重启后端。

如果修改了 Java 代码、POM 或 Flyway 迁移文件，通常需要重新启动后端。

## 7. 如何停止

停止后端：点击 IDEA 运行窗口中的停止按钮，或在运行后端的终端中按 `Ctrl + C`。

停止前端：在运行 `pnpm dev` 的 PowerShell 窗口中按：

```text
Ctrl + C
```

这只会停止前后端开发进程，不会停止单独运行的 PostgreSQL、Redis 和 MinIO。

## 8. 常见问题

### 8.1 JWT secret must contain at least 32 characters

原因：没有加载 `application-local.yml`。

使用 IDEA 时，检查运行配置中的“有效配置文件”是否为：

```text
local
```

启动日志应出现：

```text
The following 1 profile is active: "local"
```

使用命令行时，确认启动参数包含 `--spring.profiles.active=local`，或者已经设置运行所需的环境变量。

### 8.2 Vite 提示 Node.js 版本是 18

原因：当前终端仍在使用旧版 Node.js。

使用已安装的 Node.js 版本管理器切换到 22，然后重新检查：

```bash
node -v
pnpm -v
pnpm dev
```

不同版本管理器的命令不同，请以所选工具文档为准，不要在项目文档中固定某台电脑的 Node.js 安装目录。

### 8.3 Flyway checksum mismatch

原因：数据库已经执行过的迁移文件被修改了，即使只修改注释也会影响校验值。

处理原则：

- 已执行的 `V1`、`V2`、`V3` 不应继续修改。
- 新的数据库结构变化应创建 `V4`、`V5` 等后续迁移。
- 不要在没有确认数据库状态时直接执行 Flyway `repair`。

### 8.4 请求提示 401 或跳回登录页

JWT 已失效、后端刚重启或浏览器保存了旧令牌时，重新登录即可。

### 8.5 后端连接数据库较慢或超时

如果依赖服务由 Docker 提供，先在对应主机执行：

```bash
docker ps
```

确认 PostgreSQL、Redis 和 MinIO 容器处于 `Up` 或 `healthy` 状态，同时检查主机防火墙、云安全组、DNS 和本地网络。不要为了排错长期向整个公网开放数据库或缓存端口。
