# AI 助手能力发现与智能路由说明（阶段 7.3 / 7.4 基础版）

## 1. 用户看到的变化

AI 助手默认进入 `SMART AGENT / AUTO`，用户不再手动选择普通聊天、知识库增强或业务 Agent。

空白页会调用 `GET /api/ai/capabilities`，根据当前登录用户权限展示可点击示例。示例点击后只填入输入框，用户可以先修改；任何业务写操作仍必须经过二次确认。

AI 回答还可以返回 `suggestions`，前端在消息下方显示轻量按钮，帮助用户继续查询相关业务。

## 2. 能力注册表

`AgentCapabilityRegistry` 是能力元数据的统一来源，每项能力包含：

- 能力编码、名称和说明；
- 分类与风险类型；
- 所需 RBAC 权限；
- 页面示例问题；
- 提供给规划器的参数契约。

接口只返回当前用户有权使用的能力。模型规划提示词也使用同一份权限过滤结果，避免页面显示、模型规划和 Java 校验互相不一致。

## 3. 自动路由

```text
用户消息
  -> Agent 规划器
  -> DIRECT：通用回答
  -> TOOL_CALL：订单、退款、工单、分析或知识库查询
  -> ACTION_PLAN：生成需要用户确认的写操作
```

用户询问“你能做什么”时，直接回答模型会收到当前账号的真实能力清单，只允许依据清单回答。

## 4. 安全边界

- 模型输出不能生成任意 HTML、CSS 或前端组件。
- 前端仅渲染后端定义的 `content`、`sources`、`tools`、`pendingAction` 和 `suggestions`。
- 建议按钮只填充输入框，不直接调用业务写接口。
- 创建工单和追加回复继续使用十分钟确认令牌、权限复查及幂等控制。
- 没有权限的能力不会出现在接口、首页示例或模型可用工具清单中。

## 5. 下一步

阶段 7.5 已增加 `CLARIFY` 和 `UNSUPPORTED` 路由。缺少参数、表达含糊或请求未开放操作时，接口仍返回 HTTP 200，并通过 `responseType`、`missingFields` 和 `suggestions` 返回可读的中文引导。

`responseType` 可能为：

- `ANSWER`：普通回答。
- `TOOL_RESULT`：只读工具查询结果。
- `ACTION_CONFIRMATION`：需要用户确认的写操作，前端使用橙色确认卡片。
- `CLARIFICATION`：缺少参数或无法准确理解，前端使用青蓝色引导消息。
- `UNSUPPORTED`：系统尚未开放该操作，同时给出可用替代方案。
- `SYSTEM_ERROR`：保留给真实系统故障；正常的澄清与能力限制不会使用红色错误提示。

对于“再创建一个”这类可能沿用历史关键参数的短句，系统不会直接生成写操作确认，而是先询问是否沿用上一订单并要求补齐工单信息。模型生成的自由文本不会直接成为引导语，用户看到的提示由 Java 后端按意图和缺失字段生成。
