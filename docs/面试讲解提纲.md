# 面试讲解提纲

## 30 秒版本

SmartMall TLAI 是一个可部署的商城运营后台。我没有让模型直连数据库或直接执行写操作：RAG 只读 READY 文档，Analytics 使用白名单 DSL，Agent 通过工具注册表和 RBAC 选择能力，写操作还需短时令牌二次确认。整个调用链有脱敏审计和固定中文评测集。

## 5 分钟演示顺序

1. 登录后展示菜单随权限变化，并说明真正授权在后端 `@PreAuthorize`。
2. 创建订单、支付、申请并审核退款，说明条件更新和事务如何避免重复扣/加库存。
3. 上传知识文档，展示处理状态、RAG 引用和“无证据拒答”。
4. 让 Agent 查询订单并跳转到业务页面，再演示创建工单时先生成确认卡片、不立即写库。
5. 从 Agent 审计跳到同 trace 的 AI 调用日志，强调仅保存安全元数据。
6. 展示 Compose 单入口、健康检查、备份保护和离线评测报告。

## 常见追问

**为什么是模块化单体？** 业务规模尚不需要分布式复杂度，但通过 Maven 依赖方向、Repository 端口和组合根保留拆分空间。

**如何防止模型执行任意 SQL？** Planner 只能返回固定六字段 JSON；Jackson 拒绝多余字段，枚举和组合由后端校验，Mapper 中的 SQL 固定。

**如何防 Prompt Injection？** 系统提示明确把检索片段和业务 label 当作不可信数据；上下文有长度上限；最终能力仍受代码白名单和权限约束，提示词不是唯一防线。

**为什么确认令牌还要重查权限？** 权限可能在计划生成后被撤销。确认时校验 token hash、所有者、过期时间、状态和实时权限，抢占 `EXECUTING` 防并发重复写。

**密钥如何保护？** API Key 用 AES-GCM 加密，主密钥仅来自服务器环境变量。生产秘密无弱默认值，审计和错误消息不回显敏感值。

**如何验证质量？** 后端单元/契约测试覆盖状态机、认证、JWT、密文、迁移、权限、RAG、DSL 和 Agent；前端用 Node 内置测试覆盖纯策略。固定评测报告区分离线规则验证和真实模型执行。

## 可继续演进

- 将 Access Token 改为短时令牌 + HttpOnly Refresh Token，并增加会话撤销。
- 引入对象存储版本化、数据库 PITR、指标/链路采集和集中日志脱敏。
- 用真实标注集做分层评测，增加模型版本、成本、Token 和置信区间。
- 大规模后再按业务边界拆服务，并以 Outbox/事件驱动处理跨边界一致性。
